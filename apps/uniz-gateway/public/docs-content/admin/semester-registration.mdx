Semester registration in UniZ replaces external spreadsheets for subject enrollment. The full workflow runs inside the admin portal and academics API.

---

## Who does what

| Role | Responsibilities |
| ---- | ---------------- |
| **Webmaster** | Create semesters, build subject catalog, set registration window (IST), open/close registration, publish with OTP |
| **Dean** | Review and approve branch allocations across departments |
| **HOD** | Review department electives; read-only student list scoped to own branch; registration tracking for department |
| **Director / COE** | Oversight, registration tracking across branches |
| **Student** | Register mandatory + elective subjects during the open window via portal **Register** tab |

---

## Portal workflow (webmaster)

<Steps>
  <Step title="Create semester">
    Use **Semester Builder** to define name, batch, academic year, subjects, and elective groups. Save as `DRAFT` or submit directly to dean review.
  </Step>
  <Step title="Dean & HOD review">
    Dean reviews allocations per branch. HOD refines elective names/credits for their department. Status advances through `DEAN_REVIEW` → `HOD_REVIEW` → `APPROVED`.
  </Step>
  <Step title="Set registration window">
    Configure `registrationStart` and `registrationEnd` in **IST**. Students cannot register outside this window even if status is `REGISTRATION_OPEN`.
  </Step>
  <Step title="Open registration">
    Advance semester to `REGISTRATION_OPEN`. Students see the **Register** tab in the mobile dock and desktop nav.
  </Step>
  <Step title="Track completion">
    Semester cards show **Students registered** (distinct student count). Use **Registration tracking** for per-student pending/registered lists with search.
  </Step>
  <Step title="Close registration">
    Move to `REGISTRATION_CLOSED` when the window ends or manually after the deadline.
  </Step>
</Steps>

---

## Registration window (IST)

Registration open/close times are stored on the semester and interpreted in **Asia/Kolkata**. The student UI and API return clear errors when:

- Status is not `REGISTRATION_OPEN`
- Current time is before `registrationStart`
- Current time is after `registrationEnd`

Students who already registered see a locked state — re-registration is rejected with **409**.

---

## Elective groups

Group electives so students pick exactly N subjects from a set (e.g. one open elective from four options). Configure groups in Semester Builder; the registration API enforces `maxSelections` per group.

---

## Direct publish verification

Sensitive actions (opening registration or publishing results) may require email OTP:

1. Request code — sent to the webmaster's registered email
2. Confirm with `POST /academics/semester/:id/publish` and the six-digit code

This prevents accidental mass publication.

## API reference

See [Semester Registration API](/api/academics/registration) for full endpoint documentation including:

- `GET /academics/student/available`
- `POST /academics/student/register`
- `GET /academics/registrations/tracking`
- `POST /academics/semester/create`
- `POST /academics/semester/:id/advance`

## Seating arrangements

After registration, webmasters can upload exam seating via:

```bash
GET  /academics/seating/template
POST /academics/seating/upload   # multipart Excel
GET  /academics/seating/student  # student view
```

Seating is separate from subject registration but uses the same semester context.
